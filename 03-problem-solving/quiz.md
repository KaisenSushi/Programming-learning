# Quiz

[Module home](README.md) | [Exercises](exercises.md) | [Project](project.md) | [Solutions](solutions.md)

Answer without running code. Explain each answer in one or two sentences. The explanation matters because it shows whether you can transfer the idea to a new problem.

1. What four parts should a useful problem contract identify?
2. Why should you create examples before writing code?
3. What is an invariant, and how does it help justify a loop?
4. A program performs one dictionary update for each of `n` items. What is its expected time complexity?
5. A function sorts `n` values and then scans them once. What term dominates its time complexity?
6. Why can an empty input be more useful than another ordinary example?
7. What is wrong with optimizing code before confirming its behavior?
8. A duplicate detector stores every observed value in a set. What are its expected time and worst-case extra-space complexities?
9. Name two distinct failure modes for a balanced-bracket checker.
10. When a complicated test fails, why is reducing it to a smaller counterexample useful?

Check your responses against the [solutions](solutions.md). If an answer differs, return to the relevant lesson and write a new example of the concept in your own words.
