# Quiz

[Module home](README.md) | [Solutions](solutions.md)

Answer without running code first, then verify your reasoning.

1. What three stages make up a simple test?
2. Why should unrelated behaviors usually have separate test methods?
3. Which inputs are especially useful when a valid percentage ranges from zero through one hundred?
4. What information should you record before changing code during debugging?
5. Why is catching every exception with a bare `except` usually harmful?
6. When is logging more useful than an interactive breakpoint?
7. What distinguishes an integration test from a unit test?
8. Can one hundred percent statement coverage prove that a program is correct? Explain.
9. Why must tests avoid depending on execution order?
10. A test passes locally and fails in continuous integration. Name three environmental differences worth checking.

Use complete sentences for explanations. A good answer links the practice to the quality of evidence it produces. The answer key is in [solutions](solutions.md).
